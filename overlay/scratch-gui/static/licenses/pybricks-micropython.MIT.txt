Pinned Pybricks v4.0.1: 4104553405decb0384bcfb030fbfcb4b5a9854cc
Pinned MicroPython: 13580b6ad057173f62e8b2363e01d6851bcc6699
Build recipe: build-pybricks-wasm.sh; compiler input manifest: PROVENANCE.json.

The prepared build excludes the argument helper and non-free Xbox module.
Argument callers use explicit MicroPython APIs. Two cited numeric snippets
are removed and replaced by BSD-3-Clause contract-only components.
The new components have separate recorded implementation inputs and tests.
The earlier PR #508 authorship assertion remains unverified; the earlier
replacement is not used in this build. Historical evidence stays in the audit
repository, outside the shipped payload.

Permissive source components: Pybricks / MicroPython (MIT), lwrb (MIT), BBC
light-matrix font (MIT), LEGO control code (BSD-3-Clause), Contiki-derived
scheduler (BSD-3-Clause), Brickwright components (BSD-3-Clause). Emscripten,
musl and compiler-rt notices are included below. No Bluetooth stacks,
hardware vendor HALs or GPL/MPL NXT/EV3 drivers enter this simulator build.
This statement concerns this simulator, not every other Brickwright component.

Implementation of local continuations based on switch() statement

This implementation of local continuations uses the C switch()
statement to resume execution of a function somewhere inside the
function's body. The implementation is based on the fact that
switch() statements are able to jump directly into the bodies of
control structures such as if() or while() statements.

This implementation borrows heavily from Simon Tatham's coroutines
implementation in C:
http://www.chiark.greenend.org.uk/~sgtatham/coroutines.html

---------------------------------------------------------------------------

The code in this file stems from Contiki's implementation of protothreads as
listed above. This adaptation changes the API to work better with Pybricks.

Caution: it is conceptually very similar to Contiki but it cannot be used as
a drop-in replacement.
