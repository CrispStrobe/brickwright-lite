# Six Technic experiments

These original CrispStrobe models and programs use BSD-3-Clause. Official
LDraw parts retain their individual author credits and CC BY notices.

| Example | LEGO placements | Motors | Classical principle and physical comparison |
| --- | ---: | ---: | --- |
| Rod Ratio | 167 | A | Slider-crank linkage: two connecting-rod lengths give equal 48 mm strokes but different intermediate positions. |
| Vernier Drive | 176 | A | Differential reduction: opposed 1 and −27/25 branches give a passive 1/25 pointer rotation. |
| Line Turner | 145 | A | Scott–Russell linkage: a horizontal rack input produces a passive vertical straight-line output. |

| Oblique | 291 | A/B | Adjustable trammel: compare measured ellipses with the actual guide at 90° and 60°. |

Each selection loads its program into Blocks and sets the project title.
English and German lessons explain the experiment, equations and limits.
Classical names and aliases are searchable in Examples. Reset before a repeat
or after manual movement; these programs use their saved encoder datum.

Atlas Six's supplied program remains immutable in the source fixtures. Its
bundled derivative moves the identical travel-bound calculation from 27 stage
copies into one joined receiver. The six concurrent motion receivers, targets,
correction limits, final hold and watchdog remain unchanged. This reduces the
generated saved graph from 2,470 to 756 blocks. Native qualification at both
observation cadences retains the original physical and controller limits;
loading latency and the complete browser journeys are qualified separately.

Manual controls use bounded angle requests. Atlas Six's individual jogs are
deliberately small; its coordinated program demonstrates the larger six-axis
experiment. The jog limits are software requests, not physical end stops.
Atlas Six is a specifically reviewed six-port and longer-program exception;
the general model-builder limit remains one to three motors.

## Source and construction adaptations

Original models, programs, contracts and pure observers remain in the source
fixtures with hashes. `node scripts/adapt-six-technic-models.mjs --check`
reproduces the supplied models with these explicit adaptations:

- Rod Ratio's four long guide-post pins move 5 LDU along their own axes.
  Their stop collars now seat on the beam/packing interface instead of
  penetrating the guide beams. All four pins and all supports remain.
- Oblique substitutes one shorter thin six-hole roof brace. All three
  original pin connections remain, and the unused overhang clears motor B.
- License pointers name the bundled notices.

Atlas Six's stock 32195a suspension arm is bundled through the canonical,
hash-verified official LDraw subset. Its collision metadata represents the
fork walls, separate eye ends, bridge and rounded socket head. The original
mass and every connector remain unchanged. There are no model-specific
collision exclusions. Negative controls move an insert into a real fork wall
and restore Oblique's old brace, which must reproduce their respective failures.

## Qualification boundaries

The native suite runs each finite program at both 25 ms and 30 Hz observation
cadences with unchanged 5 ms physics. It retains the original motion,
geometry, closure, guide engagement, startup, return, hold, independent marker
and controller limits. Current source and engine identities are recorded
separately from the immutable original contracts. Freezing actual output
observations must fail; API observation must leave native trajectories unchanged.

These six examples contain physical comparisons inside their own assemblies
or routes. Their specific comparisons are registered by the reviewer. Other
intakes still require their existing disconnected-mechanism controls.

Project saves, model-file exports and Build-to-Simulate retain twelve decimal places for precise authored joint geometry;
the default standalone writer retains its existing six-decimal output. Source
binding accepts only the reviewed model or its exact canonical project-save
derivative, with unchanged compiled-geometry and motion tolerances.

Browser qualification separately checks actual worker poses and API calls,
program completion, hold, manual controls and Stop, visible PNG pixels,
connected instructions, placement BOM, raw LDR/MPD imports, actual project save
and fresh-context program replay, bilingual lessons and library export.
The browser's paused initial snapshot does not establish an unpowered startup
interval; that remains a mandatory native check. Source-binding comparisons
allow only numerical roundoff between JavaScript engines, independently of
the unchanged physical tolerances. Compiled gear identities remain exact;
computed ratios admit only binary arithmetic roundoff and are independently
checked against the observed shaft motions.

Fixed-period hold checks compare integer tick spans at exact sampled boundaries,
so subtraction of late floating timestamps cannot turn one allowed frame into a
false failure. Non-grid observations keep the direct comparison; short-hold
negative controls retain the original one-frame allowance. Immutable supplied
oracles remain in the fixtures alongside the reviewed numerical correction.

Saved-project checks wait for the saved program and loading overlay before
operating the restored editor, within the existing 120-second import budget.
Atlas Six’s browser wall wait derives from its named 490-second simulated
program envelope; other examples retain their prior wall waits. The physical
program watchdogs and motion limits are unchanged.

Screenshot capture checks font availability in every frame. An observed WebKit
case leaves its readiness promise pending with an empty, loaded font set. Only
that case, with available system fonts independently checked before and after
capture, can use the scoped screenshot workaround. Actual pending custom fonts
still block capture; blank-canvas negatives and unchanged model-pixel thresholds
remain mandatory. The application DOM and fonts are never altered by capture.

The qualification runner produces a source-bound receipt for these checks.
Simulation qualification does not certify a physical build, friction, wear, cable routing
or LEGO motor load capacity.
