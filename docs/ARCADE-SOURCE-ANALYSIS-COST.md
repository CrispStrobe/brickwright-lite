# Arcade source analysis cost

## Declaration identity during translation

Procedure constraint preparation needs to identify a unique, unchanged function declaration. Its initial producer analysis does not consume propagated value types. The focused candidate uses the same lexical analyzer to obtain only declaration identity at this one internal preparation boundary.

The analyzer still visits declarations, lexical scopes and every physical writer, including unreachable writes. It retains print and initialization traversal, class-call classification, recursive call classification and formal argument setup. Recursive declaration identity remains distinct from immutable function or result production.

The optional shortcut checks the actual Program's own data, object identities and relevant intrinsic descriptors. Unsupported structure or changed observations falls back to the original eager analysis. Throw-containing Programs retain the original exceptional completion analysis. Existing public analysis and preparation entries remain eager; no caller option or annotation selects the shortcut.

The callable admission checks, all selected and empty-selection constraint validation, omitted-default lowering and validation of the lowered Program remain required. The identity view supplies no value types, binding maps or completion certificate. This changes analysis work, not supported source features or conversion policy.

## Checks and limits

The focused module has seventeen passing groups: nine existing controls and eight comparisons with the eager analyzer. They cover lexical identity, recursion, exceptional reachability, argument production, defaults, diagnostics, malformed structure, physical replacement, changed metadata, external AST behavior and changed intrinsics. The new private views use the captured freeze intrinsic while existing eager graph observations remain unchanged.

A separate paired comparison uses seven fixed public imports with the same files, options and order for each variant. It compares full returned values or errors with exact deep equality and records process CPU and elapsed time. A single ordered pair per case remains subject to startup, JIT and host noise. Shortcut usage is not instrumented.

Focused component tests do not qualify the full composed regression suite, complete conversion corpus, runtime, editor, or game behavior. Earlier measurements of a separate syntax-observation cache did not establish a useful improvement on the real application inputs; that candidate remains unselected.

The paired run returned exactly equal full results for all seven inputs. Aggregate process CPU was 6.929 seconds for the baseline and 6.521 seconds for the candidate (about 5.9% lower). Across the four real application inputs it was 5.622 versus 5.342 seconds (about 5.0% lower). Results were mixed: one real input used 1.222 versus 1.536 seconds. These are single ordered samples, not a uniform speedup, a statistically established performance result, or proof that the full corpus fits its limits.

## Remaining qualification

This is a reviewed local component candidate, not a qualified main-branch composition. Integration still needs the complete composed regression modules, full conversion census and affected guest qualification under the existing limits. Incomplete runs retain their unobserved remainder and provide no whole-suite or corpus pass claim. No syntax-observation cache from the earlier unselected candidate is included.
