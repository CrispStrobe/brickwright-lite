# Functional contract — independent SPIKE backend
Coordinator-authored API specification; observations.json contains synthetic black-box motor measurements. No implementation/source algorithms supplied. Newly authored work BSD-3-Clause, copyright 2026 Brickwright contributors.

Implement only in this directory: backend.js and backend.test.mjs. No dependencies, imports of project code, web, network or oracle runtime access. Node builtins for your own tests allowed. You have no inherited history. Filesystem/network restrictions are instruction-based because kernel namespace isolation is denied. Do not inspect any path outside this directory, other than executing the installed node/python/shell tools. Keep all reads, writes and tests within this directory. Do not read agent sessions or other logs. Coordinator integrates afterward.

Export default class IndependentSpikeBackend; named MAX_DEG_PER_S, DEFAULT_MAX_DEG_PER_S, RESULT. Constructor(hubState, options={}) accepts a neutral interface: hubState.data = {motors: six mutable {position: degrees, speed: percent, degPerSec?: degrees/second}, sensors: six nullable {kind,deviceId,...}, classicPorts: six [deviceId,values], display: 25 brightness levels 0..9, imu:{yaw,pitch,roll,acceleration,angularVelocity}, buttons:{left,center,right}, volume,centerLight,distanceLights}; hubState.changed() notifies subscribers. Backend must use this shared data, with no duplicate physical motor positions or sensors. It may maintain command/controller/scheduler bookkeeping. Existing licensed adapters parse program commands and convert units; they will call this interface.

Motor methods: maxSpeed(port), percentToDps(port,percent), runAtSpeed(port,dps) (continuous, returns void), runForDegrees(port,degrees,dps), runForTime(port,ms,dps), runToPosition(port,position,dps) (finite commands return Promise<'completed'|'interrupted'|'stalled'>), stop(port,action='brake'), stopAll(), cancel() (hard zero all motion and interrupt all pending commands/waits), resetPosition(port,value=0), busy(port), step(dtMs)->boolean moved. Port A-F case-insensitive or integer 0..5; invalid throws RangeError before mutation. Speeds clamp to device limit: ids 48/75 1110,49/76 1050,65 660 deg/s, fallback1110. Percent clamp -100..100. Device 48 additionally applies a measured synthetic shaft envelope of 950 deg/s to continuous, position and timed commands, without changing its nominal API limit or percent conversion; other devices retain nominal limiting. Nonfinite motion values throw TypeError, negative dt/durations RangeError. degrees signed; direction sign(degrees)*sign(dps). Absolute target ignores sign of speed. Zero distance completes immediately; zero speed nonzero position command rejects RangeError to avoid hanging; zero-speed timed commands wait out duration. New command or stop interrupts previous finite command exactly once. Different ports independent. resetPosition changes counted angle without commanding motion. Motor command ensures sensor kind motor (unknown devices may be attached by command for existing adapters). Idle sensor ports must not become motors during stopAll or stepping. Publish classic motor [deviceId,[rounded speed percent,rounded angle,0,rounded speed percent]]. Motor data.speed is actual current percent, degPerSec actual shaft speed; preserve untouched idle ports so external backend may write them.

Default finite acceleration/deceleration 1500 deg/s². Expose configure(port,{acceleration,deceleration,coastDeceleration,brakeDeceleration,stallMs,stallSpeed}) and setLoad(port, fraction in [0,1]); explicit synthetic load fraction1 is locked shaft, finite position commands terminate stalled after stallMs (default 500ms); continuous motor stays commanded/stalled until changed; report motor.stalled. Partial load reduces attainable speed. No claim of physical accuracy for this load model. Expose done(port): true for settled finite tasks or steady speed commands, false during finite task or ramp; busy means commanded motion including continuous. Stops retain nonzero velocity while decelerating; hold must settle and retain its captured position, brake dissipates faster than coast by default (brake6000, coast1500 deg/s²). Intentional difference from oracle: shipped oracle stop/coast/brake measurements coincide; our coast/brake distinction is specified simulator behavior. stopAll/cancel hard stop for disconnect/reset safety. Target trajectories ramp up/down and settle within 0.5 degrees and 1 deg/s, target may finish exactly; never teleport entire target. Timed command's duration includes speed ramp and planned deceleration (settle no later than duration+10ms in unloaded case). Controller design entirely your choice.

Deterministic simulated time: step advances only supplied dt, identical results for a single dt versus multiple chunks (use a consistent small simulation quantum and remainder if desired); no wall-clock reads in physics. Expose simulatedMs, wait(ms,{signal}={}) resolves completed after supplied simulated time; cancellation resolves interrupted, invalid arguments reject before queuing. Concurrent waits independent; already-aborted signal returns interrupted. Optional async pace(ms,{realtime=false,signal}={}) advances via step in deterministic chunks, optional wall-time pacing, yielding host event loop to allow cancellation; coordinator will avoid pace when arena owns clock. Expose dispose() cancels and removes abort handlers; never leave an unresolved wait on cancel/dispose.

Sensor/hub interface: readSensor(port,kind) returns copy of current shared sensor or throws Error for absent/mismatched device; units distance mm(-1 absent reading), force percent of10N, color id -1..10 and reflection/ambient %, raw RGB 0..1024. imu() and buttons() return copies of current shared inputs; setPixels(25 levels) validates/clamps 0..9; setPixel(x,y,brightness) validates indices then clamps brightness and writes y*5+x; setLight(0..11),setVolume(0..100),setDistanceLights(port,four levels0..9) validate; call changed on output writes. No independent sensor simulation: arena supplies readings. Scheduler advances from same step as motors.

## Coordinator functional addendum

These are additional neutral interface requirements supplied by the coordinator as functional prose, without implementation source or algorithms.

- Optional hubState.clockOwner: native motion commands and pace reject Error when set to any value other than 'native'; wait rejects before queueing in that case, and step returns false without advancing time/state. cancel/stopAll remain available for safety handover. Only one pace driver is allowed; overlapping pace rejects. Ownership changes during pace interrupt its own wait, with no unresolved promise.
- Shared motor.speed is rounded percent; degPerSec preserves exact shaft speed. RESULT exposes uppercase and lowercase completed/interrupted/stalled keys.
- step does not notify subscribers: the world owner publishes motor and arena inputs atomically afterward. Standalone pace notifies after each step. stopAll/cancel support {notify:false} for quiet safety reset, while defaults notify.
- setStopAction(port,action) validates coast/brake/hold and stores the per-port configured default in motor.stopAction. Defaults are brake. stop(port) uses that configured default; explicit stop(port,action) overrides only that stop, without changing the configured default. The most recent explicit or default stop is observable as motor.lastStopAction. Finite target/time commands honor configured defaults on successful completion: hold retains the settled target as an active regulator while done is true; coast/brake settle without an active target. Zero-distance/zero-duration successful completion follows the same default-action rule.
- beep(frequencyHz,durationMs,{waveform='sin'}={}) returns Promise completed/interrupted. Frequencies and durations are finite nonnegative numbers; supported waveforms are sin/square/triangle/sawtooth. Invalid inputs reject before mutation. Each valid beep increments shared speaker.beeps, sets shared speaker.waveform and frequency, and preserves optional speaker metadata such as volume. Missing speaker data may be initialized as {frequency:0,waveform:'sin',beeps:0}.
- Replacing a beep interrupts the previous beep exactly once. stopSound interrupts the current beep and sets speaker.frequency to zero. step supplied time completes a beep at its simulated deadline and silences it, without publishing a hub notification. cancel/dispose silence sound and interrupt a pending beep. Zero duration completes immediately and silently; zero frequency remains a silent timed beep. Optional constructor options.onBeep(frequency) receives frequency changes, including silencing. Beeps require native ownership of the simulated clock. Media file playback is outside this support contract.
