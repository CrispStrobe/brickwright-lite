# Ordinary handler-record Arrays with primitive callbacks

PROPOSED, NOT IMPLEMENTED OR QUALIFIED. This contract claims a bounded ordinary
class collection bridge after its normal qualified merge. It changes no live
claim, default admission, dependency pin or native value protocol by itself.

## Concrete requirement and first subset

Retained Sprite Utils v0.3.1 `spriteutils.ts` stores handler objects in Arrays
and invokes each object's callback. Retained State Transitions v0.0.2 `main.ts`
stores `EventHandler<U>` objects, replaces an existing callback or appends a new
record, then selects and invokes it. These inputs motivate shared mechanisms;
the first subset does not admit either complete library, their Sprite values,
generic classes, inheritance or scene scheduling.

Start with a one-dimensional Array whose actual elements are completed instances
of one proved ordinary handler class. Its primitive fields and one typed callback
field have explicit constructor assignments. The Array is created by an actual
empty Array allocation and may be held in an ordinary registry field and actual
scoped aliases. Prove append, indexed read, replacement and removal individually,
using existing editable operations where their semantics suffice. Preserve actual
iteration/index and mutation behavior; do not substitute a snapshot traversal.
One concrete handler type and exact callback signature govern each Array. Other
ordinary classes named Handler or Registry gain no authority from those names.

Callbacks have supported fixed primitive parameters and a primitive or Void
result. Qualify Number and Void paths first, with separate concrete signatures;
String and Boolean require the same actual producer and native checks before
admission. A Void action must complete before the following operation, including
when it pauses. No union with Any, opaque result or missing argument is inferred.
Direct Arrays of callable values, nested Arrays, heterogeneous record types,
Array results from callbacks and generic class element parameters remain named
refusals until separately proved. Existing qualified method-generic substitution
stays invocation-local; it must not become a shared first-call specialization or
accidentally grant a generic class/Array schema.

## Types constrain actual allocations and mutable identity

Current syntax can parse an Array type without admitting it in a class callable
plan or native signature. A new bounded structural type/element certificate, if
needed, must identify the actual ordinary class and exact callback signature and
be validated consistently in source, native plan and current export. Merely
adding an Array branch to the type parser or treating `Handler[]` as a named
class is insufficient. Constraints never create an Array, handler or callable.

Use directed actual Array allocation, constructor completion, element insertion,
record-field assignment and callback creation facts. Prove initialization and
read dominance, every incoming call and every actual writer even if unused,
later or in another original target. Follow aliases by actual lexical or variable
identity, not matching names or current equal values. Include Array-cell and
field reassignment, index writes, append/insert/removal/length operations and
captured/formal writers. Unresolved receiver, computed storage name, escaped
writer, duplicate declaration or cyclic ownership cannot be ignored. An unrelated
opaque sibling cell must not poison a separately proved primitive/callback cell.

Array element constraints apply independently to every actual insertion and
replacement, including empty Arrays with no concrete element yet. Empty storage
has no invented element producer; a typed read from it still requires actual
presence proof. Out-of-range, sparse or shrink-exposed reads retain genuine
Undefined and cannot be invoked as a handler. Optional/default/nullable values
need their independent current presence proof, never an annotation grant.

Array, record and callable identities are distinct. Array aliases share one
mutable Array; repeated reads of an existing record retain its object identity;
its action retains the actual closure and live captured cells. Removing a record
from an Array does not fabricate object destruction or invalidate an otherwise
live alias. Replacing `record.action` affects subsequent reads, not an already
saved action read. A saved selected record/action must be tied to that actual
read and invocation, with body/graph edit invalidation, rather than re-read from
a changed Array index or backing field at completion. Preserve the existing
conditional read and single-use completion certificates.

## Native transport and actual boundary ownership

Audit existing BW Array, object and callable reference transports first. The
runtime Array heap provides mutable Array identity; object and callable services
own their bodies and generations separately. An array-shaped reference or an
existing heap entry alone does not prove its current elements or callbacks.
Do not flatten records/actions to JSON, clone away alias identity, wrap actions
as fake ordinary objects or accept a signature marker as a resource.

Validate original raw ingress before codec restoration at every admitted Array,
record and callback constructor, field, argument and result boundary, including
unused typed parameters. Exact reference shapes, scopes and current bodies must
be proved before normalization can erase extra fields or custom accessors.
Coerce any supported serialized argument text once: checked and dispatched values
must come from the same snapshot. Do not normalize String numeric text from a
Number constraint; only the existing actual physical Number input proof applies.
If existing transport cannot preserve these obligations, retain an explicit
refusal and qualify a separately claimed supplier change before admission.

Use actual current runtime/target, Array allocation, class heap body and callable
resource/declaration/procedure ownership. Each component's existing lifecycle
remains distinct. Reject foreign, stale, fabricated, disposed or bodyless values
and remapped/reused IDs. Stop must revoke callable invocations, captured-frame
leases and pending completion/read tickets; a surviving Array or ordinary object
must not revive its stored old action. Repeat Start and successful project Load
must create the proper fresh generations; disposed services cannot be revived by
Start. Preserve legitimate load and new allocation behavior without listener
exceptions aborting unrelated services.

Invoke real managed callback procedures with ordered arguments and captured
cells. Prove actual callback completion, exactly-once settlement and current
result type before advancing the caller. Reentrant mutation, pause, Stop,
project replacement and failure must not forge completion or leave an owned
waiter permanently suspended. Any Throw integration requires its own separately qualified exceptional-handoff
boundary; an exception must not become a normal Void/Undefined completion. Array mutation and
runtime effects do not authorize a changed current Blocks graph or stale method
body. No global HAT/name/caller flag or observer can issue invocation authority.

## Current source, Blocks and export obligations

Fresh source imports retain the actual Array element/callback constraints as
editable current declarations and operations, with complete directed producer
proof. Current Blocks independently bind actual variable IDs, class/procedure
registrations and ordered formals, connected Array/record/action producers,
all writers, element read/presence and callback invocation. Validate actual
mutations and effect order; do not use saved runtime values to repair edits.

Reconstruct current TypeScript with genuine typed Array/handler/callback shapes
and ordinary constructor/method bodies, then independently reprove that output.
Do not restore original source, drop unused helpers, manufacture calls, widen
unknowns to Any or borrow source annotations as value facts. Declaration-only
constraints from the ordinary procedure protocol may remain obligations, but
cannot seed actual elements, actions, Console, Font or SDK producer facts.
All adjacent unsupported bodies must still prevent whole-program admission.

Demonstrate native, Code, same/fresh saved SB3, save/reopen, edited current
initializer/action/argument, export/reimport and actual callback alias mutation.
Exercise real visible Array and class/callback authoring routes. Record missing
palette, field or declaration controls explicitly; native-only roundtrips do not
qualify an installed GUI. A new canonical declaration/operation word or schema
needs its own supplier claim, tests, normal merge and consumer adoption.

## Minimum acceptance and mandatory refusals

An authored primitive-only registry appends two distinct handler records whose
closures share a real captured counter. Select one, retain a record alias and a
saved action, replace its action through the alias, remove the record from the
Array, and invoke both saved and newly read actions with exact distinct results.
Also retain an Array alias and prove replacement/removal and length are shared.
Use a separate Void-signature registry with a pausing action to prove serial
trace order and exactly-once effects before a subsequent action or caller step.
Change an actual current Number initializer or callback body and observe the
changed portable result; do not substitute a frozen source result.

Refusals include annotation-only/producerless elements; missing construction or
callback completion; wrong record class/signature/result; unused incompatible
argument; later or foreign writer; captured/formal/index/Array alias mutation
from an opaque source; forged or extra-field reference transport; unknown
computed receiver/storage; empty/out-of-range/shrunk read without presence;
duplicate or foreign registrations; body/condition/input/next/substack edits after
a saved read; stale resources/tickets after Stop, repeated Start, clear and Load;
and ordinary objects or strings masquerading as Array/callable resources.
Positive controls must distinguish an unrelated sibling's opaque writer and a
legitimate post-read backing-field mutation from an authority-breaking graph edit.

Freeze the complete affected source and provider and obtain independent review.
Genuinely new selected-original source and actual edited-export programs require
frozen inputs, current shared guards and a fresh reservation. Reuse unchanged
successful originals only with byte equality; no observation-only replay merely
to publish. Default admission stays closed until every bounded route and lifetime
control qualifies; publish exact residuals and observed boundaries.

## Work kept separate

The primitive Array.map contract computes a fresh primitive result Array from
an actual receiver and inline callback. It does not authorize stored handler
records, callable element identity or collection signatures. Conversely this
contract grants no map/filter/some/sort implementation from an Array annotation.
The owned SDK Sprite contract must independently solve physical issued-value
transport and scene/body ownership before Sprite-valued handlers enter this
collection domain. Image, Font, Player, Sprite inheritance, scene event contexts,
generic class containers, direct callable Arrays and broad SDK APIs remain
excluded. No full StatusBar, SpriteUtils, State Transitions or game promotion
follows from the ordinary primitive handler registry alone.
