# Arcade callable lexical bridge — qualification prototype

Default source callable admission remains closed. This checkpoint prepares real
lexical closures; it does not qualify arbitrary callbacks, classes or a GUI
function editor. The implementation must pass source, native, Code, saved and
fresh SB3, selected MakeCode export, and reimport before admission changes.

## Owned ABI

The six native words cover callable-body declaration, resource creation,
ordered invocation, a service hat, its dispatch body, and source-variable
signature declaration. A source declaration connects a real stock variable
reporter. Its stable variable ID, actual owner, fixed signature and current
command identity authorize the source prelude. Callable remains outside scalar
and object-reference type domains.

The existing source prelude receives an optional additional declaration service.
Every mixed declaration and duplicate is validated before any variable receives
`undefined`. Running a declaration command again checks the active binding and
never resets a value. Ordinary Scratch saved defaults are unaffected.

Executable bodies remain current procedure blocks. The inert versioned lexical
plan contains owner, source-site, binding, capture-mode and concrete signature
identities; it contains no executable body. Export must validate current
procedure parameters, creation owners, declaration envelopes and service hats.
It reconstructs genuine Arrow or FunctionExpression syntax and compiles current
edited blocks. It must not restore a retained original AST body or substitute
record-backed pseudo-functions or wrapper thunks.

Source creation requires the actual lexical factory frame, not merely a local
with the same name. Global callable bindings use connected variable IDs. Local
captures use actual frame cells. Written captures share cells; readonly
captures snapshot values. Separate captured creations are distinct actions;
noncapturing creations of one source site reuse its code label. Selected PXT
reports actions as `object` and code labels as `function`; codec data transport
alone grants neither invocation nor callable typeof authority.

## Current bounded implementation

- Opt-in parser provenance distinguishes actual arrow and ordinary function
  expressions and their literal default prologues. Default parser output is
  unchanged.
- Concrete scalar callable signatures and lexical owners are retained.
- Current graph checks reject changed parameters, moved or duplicate creation
  sites, foreign/cyclic edges, forged metadata and altered service bodies.
- Native resources require current registered native procedure ownership.
  Stop, load and disposal invalidate references and pending service requests.
- Source declaration prefix validation includes fixed signature text, real
  variable IDs, duplicates and post-prelude mutation checks.

## Bounded current-body exporter

The first exporter supports straight-line concrete scalar closure bodies and
actual nested creation sites. A body edit that changes the registered return or
capture-assignment type is refused. Creation before its native local cell
initialization, control-dependent creation, readonly snapshot parameter writes,
unknown edited reporter types and unsupported declaration syntax are named
boundaries. Typed Arrow result annotations are not required in emitted syntax;
the containing genuine function signature remains explicit and the current
Arrow body determines its inferred result. No original body is restored.

Numeric, Boolean and String results from the internally tagged callable
invocation participate in the existing scalar source prelude. Authored
namespace names cannot seed that type authority. Callable declarations remain
separate and use their connected variable identities.

## Portable variable identity seal

The compiler materializes a lexical declaration's real connected stock variable
ID into its recognized versioned signature envelope. A spelling companion
prevents Code from refreshing a declaration-only rewire as if it were a valid
rename. Source envelopes reject unknown fields, missing IDs and nonvariable or
computed signature inputs. The native scanner and exporter require the stored
ID to match the current connected reporter and the companion to match its
lexical plan binding. This does not use the current displayed variable name as
runtime identity.

A saved-project rename preserves the ID. Code generation validates that ID,
updates the spelling companion and corresponding inert global native-name rows
from the actual variable, and leaves source names and executable bodies intact.
Deliberate Code reparse refreshes generated IDs after that consistency check.
Same-signature ID swaps, deleted/foreign IDs and declaration-only Code rewires
are refused. Bare concrete native signatures have no lexical source authority.

## Prepared semantic source gate

The prepared gate is not connected to default source admission. Its first
eligible shape is a module factory with numeric parameters returning a
zero-argument Arrow that captures mutable numeric local cells. The factory and
closure have straight-line numeric assignments and final returns. Names and
package identities do not authorize this shape. Defaults, optional parameters,
generics, nested owners, receiver captures, unrelated host callbacks and broader
function shapes retain explicit refusals.

The genuine exporter may declare a numeric local as `undefined` before assigning
its numeric value. That first local initializer is accepted only when an actual
numeric assignment dominates every read and capture. Undefined does not count
as numeric initialization. Repeated or later undefined assignments and writes
of undefined to parameters or captures remain refused by the current graph.

A pure operator helper may be normalized only from its actual single-return
body and resolved lexical parameter bindings. Every use must have concrete,
side-effect-free numeric operands. Each operand remains evaluated once, in
left-to-right order. Helper spelling and `any` annotations supply no authority;
string, mixed, opaque, escaped, defaulted or effectful helper uses are refused.

Forty focused controls cover the current prototype, including renamed factories,
parameters and locals, distinct increments, aliases, current-body export edits,
portable seals, lifecycle and the normalized export cases. The current edited
export still matches the retained executed SDK files and binary byte receipts.
This does not qualify callable source `typeof`, general higher-order callbacks,
classes or hosted GUI authoring.
