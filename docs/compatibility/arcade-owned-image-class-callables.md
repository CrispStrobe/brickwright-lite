# Owned Images in ordinary class callbacks

PROPOSED. Merge this ownership claim before production changes. The first slice
extends the qualified ordinary class/callable proof with live SDK Image values.
It reuses existing Image operations and the six-word callable ABI. It does not
adopt a supplier, change a pin or enable physical Sprite callback signatures.

## Actual dependency requirement

The retained MIT StatusBar v0.4.1 source stores an Image in its ordinary status
object, renders into that same Image, and passes it to the physical Sprite after
the action and display update. Sprite Utils v0.3.1 also declares a render callback
whose argument is an Image. These require real Image identity and mutations
across class fields and callbacks. Their full libraries additionally depend on
physical Sprite classes, registration, arrays and other source bodies. This
bounded slice does not qualify either complete library or an authored game.

Start with an independently authored ordinary Image holder and a generic
`apply<T>(action: (image: Image) => T): T`. Qualify separately inferred primitive,
Image and Void results; preserve the same Image through constructor parameters,
fields, aliases, captures, callback arguments and returned values. A returned
Image is the actual input or an actual supported allocation, not a reconstructed
record, texture, Sprite handle or copied pixel array.

## Source and native authority

Annotations constrain accepted producers; they never create an Image. Prove
actual unshadowed SDK Image producers and all connected aliases and writers.
The initial producer set is literal Images, `image.create` with actual numeric
arguments, and clone of an already proved Image. Other producers, including
screen and Sprite image views, need their own explicit connected-producer and
alias proof before admission. Uninitialized, optional or mixed values remain
refusals unless the existing independent presence proof proves the actual read.
Keep lexical binding identity, evaluation order and initialization dominance.
Unknown neighboring bodies, opaque casts, overridden factories, local or formal
SDK shadowing, unsupported computed calls and captured writer channels refuse.

An Image signature is a distinct qualified SDK value domain. It does not make
Image an ordinary managed class, permit `new Image`, support SDK inheritance,
or make an authored class named Image authoritative. Do not widen Sprite,
Buffer, Font, arbitrary reference kinds, Function, Any or unknown domains.

Native validation requires the current extension, exact image service identity,
current runtime reference scope, and the actual live Image body owned by that
service. A codec reference alone supplies transport, not Image body authority.
Validate all typed field writes and reads and every supported constructor,
callback argument and result boundary. Generic substitutions remain local to
an invocation. Do not specialize a shared generic method from its first call.
Preserve the existing class frame issuer, actual receiver, capture cells,
current procedure graph, conditional result certificate and completion tickets.

Plain objects, bodyless carriers, fake or foreign IDs, stale references and
replaced services must refuse. Stop, restart, Load and dispose retain their
actual Image and callable lifetime rules. Observe pixel identity and mutation
through legitimate restart/reload; do not invent a new disposal or reset rule.
An owned mutation must remain visible through every live Image alias.

## Current Blocks and export

Validate the current class catalogue, lexical plan, real variable IDs, every
relevant writer, actual ordered invocation arguments and current connected
callback bodies. A declared Image field or signature alone is insufficient.
Disconnected, foreign, ambiguous, computed or later writers cannot establish
an earlier producer. Keep source and edited-project proofs consistent.

Export actual current Image expressions and edited bodies into ordinary SDK
Image parameters, fields, Arrows and returns. Reconstruct neither a retained
AST body nor a metadata wrapper in place of edited blocks. A scalar, Sprite
String or forged Image-looking field edit must produce a named refusal.
Current constructor startup proof, conditional locals, Void discard semantics,
source declaration seals and callable label/action identity remain intact.

Use the existing Image editor and Blocks vocabulary for visible controls.
Record remaining class palette/function/handler editability gaps explicitly;
source/native success is not a hosted GUI or complete library qualification.

## Ownership and qualification

Own new Image domain producer/owner helpers and focused tests; coordinate narrow
hooks in class source flow/gates, callable descriptors and v2 plan validation,
class native types/host/field services, object class lowering, current-project
provider and lexical exporter. Preserve the Console, finite Number carrier and
identifier compound-assignment lanes. The numeric v1 gate stays unchanged.
The default class gate opens only the fully proved Image subset after review.

The current canonical Arrays codec already transports Image references. No
Extensions implementation or schema change is claimed here. If an actual
transport gap appears, prepare a separately owned supplier claim and exact-head
qualification before consumer adoption. Do not copy a held prototype or add a
new callable word to bypass a missing producer or owner check.

Required gates are pure source and current-project adversaries; real native
field/argument/result identity and full pixel checks; capture/generic/lifetime
controls; current edited Blocks and Code; same/fresh SB3; actual export and
native reimport. New selected-original source and edited-export programs require
serialized execution, exact compiled inputs and binaries, observations, and
unchanged consumed SDK/helper guards. Retained originals may be reused only
with byte-identical inputs. Preserve first failures. Independent review and
all enabled exact-head checks precede normal matched-head integration.
