# Owned SDK Sprite values in ordinary class callbacks

PROPOSED, NOT IMPLEMENTED OR QUALIFIED. This contract is prepared for the next
joint ownership composition. It does not change the current live claim branch,
source admission, native behavior, reference ABI or dependency pins.

## Bounded requirement

Retained StatusBar v0.4.1 `status-bar.ts` stores and forwards physical Sprite
values alongside ordinary status objects. Sprite Utils v0.3.1 `spriteutils.ts`
stores Sprite update handlers, and Carnival v0.0.7 `carnival.ts` stores a physical
Sprite in `Ball`. These are prerequisites within six retained class-dependent
contexts, not a promise to admit any full library or game.

The first authored control is an ordinary holder of a Sprite allocated by the
actual unshadowed `sprites.create` path, with a callback receiving that same
Sprite and returning a Number, Void or that same proved Sprite. Preserve identity
through fields, aliases, captures and returns. Start with actual owned Image
input and a proved numeric kind. Admit only separately proved `x`/`y` reads and
writes, `width`/`height` reads, and `setPosition(x, y)` with two actual Number
arguments. This list constrains an already proved receiver; it issues no value.
No neighboring Sprite property or method follows from its name or annotation.

## Source producers and transport

Use a disjoint SDK signature leaf for Sprite, separate from an ordinary class
named Sprite, the Image SDK leaf and arbitrary strings. Qualified annotations
constrain actual producers; they do not create facts. Prove the real lexical
SDK binding, constructor arguments, Image body/resource and numeric kind before
issuing a source allocation fact. Reject overridden/shadowed factories, casts,
opaque or mixed writers, missing arguments, uninitialized reads and unsupported
computed/deferred producers. Preserve actual creation-handler completion and
argument evaluation once and in order; a pending or failed creation is not a
completed Sprite allocation.

Current native `_sprite(value)` converts its input with `String(value)` and
looks up a scene table. Equality with a live ID therefore cannot distinguish an
authored string from an issued Sprite value. The new typed boundary must not use
that lookup alone, a public carrier flag or a self-issued annotation as authority.
Audit the actual canonical transport first. Use an owner-issued capability and
private current-boundary provenance that survives every qualified field, alias,
capture, argument and return path; raw ID text must not acquire that capability.
If the existing codec cannot represent this distinction, stop the consumer slice
at an explicit refusal until the required supplier schema is separately claimed,
qualified and adopted. No new reference kind, word or pin is implicit here.

## Native owner and lifetime

Follow the Image bridge's inert constructor and actual-start pattern, not its
body representation by analogy. Bind the actual runtime, extension/service,
program session, scene identity and sprite allocation body using current owned
registries and exact object identity. Reprove that the body is the completed
allocation and is registered in its actual eligible scene. The global historical
Sprite map and current scene table have different duties; neither independently
establishes all these facts. Validate producer Image/costume identity and actual
dimensions without inventing artwork, fallback dimensions or a replacement body.

Validate raw ingress before codec/heap normalization at every constructor,
field, method, callback and result boundary, including unused typed parameters.
Coerce serialized argument text once; checked and dispatched values must derive
from that same snapshot. Exact SDK role markers must agree with the existing
single signatures and current actual registration catalogue. Missing, extra or
forged markers cannot erase the obligation.

Reject foreign runtimes, forged/bodyless carriers, raw strings, replaced bodies,
reused IDs, stale sessions and disposed owners. Ordinary Stop, restart, project
clear and successful Load must retain their actual separate callable and physical
body lifetimes. Shared lifecycle listeners must not revive or throw on disposed
owners; legitimate Load may create a new inert owner. Record actual destruction
and scene transitions: native historical bodies can outlive scene membership, so
map disappearance, destruction and owner revocation must not be conflated. The
first typed subset excludes destroyed values and cross-scene transfers until
those observations and boundaries are independently qualified; it does not alter
existing Sprite algorithms or claim their post-destruction behavior is invalid.

## Class flow and current authoring

Prove all actual writers, read initialization/dominance, constructor completion,
actual capture bindings and every supported argument/result. Defaults and missing
values require the existing independent presence proof; they never borrow a
Sprite annotation. Generic substitution is per invocation from actual compatible
values, not a first-call specialization. Preserve actual class frames, receiver
identity, conditional result certificates and single-use completion tickets.

For current Blocks, bind actual variable IDs, procedure/catalogue identities,
connected producer inputs, current resource pixels, body operations and every
writer/ingress/result. A source fact or saved field value cannot repair a changed
or disconnected block. Reconstruct current TypeScript and independently reprove
that actual output; do not restore retained source. Require source, Code,
same/fresh SB3, alias mutation, edited Number inputs, save/reopen and current
export/reimport controls. Renamed targets or remapped asset IDs must still use
the actual resource snapshot; names or content hashes alone grant no body.

Exercise the real existing Sprite creation/costume editor, Number property and
callback controls through Code and Blocks. Record absent field/callback palette
or GUI editing routes explicitly. Native tests do not qualify the hosted GUI.
Any new selected-original inputs require frozen source/export bytes, fresh shared
guards and the normal reservation; retained successes are not replayed unchanged.

## Separate work and acceptance

This is not SDK Sprite inheritance, `new Sprite`, subclass registration,
BaseSprite/ExtendableSprite, physical scene factories, scene callbacks, Sprite
image views, arbitrary generic callbacks, callable Arrays or broad Sprite APIs.
The inheritance owner's current ordinary class factory/field export correction
checks primitive constraints only; it issues no runtime Sprite capability and is
neither replaced nor promoted by this contract.

Own isolated SDK Sprite producer/owner helpers and focused tests, coordinating
narrow optional hooks with the class source/current-project and native boundary
owners. Preserve Image, Console, named declarations, Arrays and result-flow
contracts. Keep default admission closed until complete source/current graph,
native lifetime, editable portable routes and genuinely new selected-original
source plus edited export agree. Publish the exact bounded result and remaining
refusals; the raw corpus and full-context counts change only after actual checks.

## Proposed coordinated Sprite handler-record extension

Implementation of this extension waits for the normal merge of this amendment.
The existing exclusions stay in force until the corresponding producer,
transport, current-project and lifetime proofs qualify. The first retained
Sprite Utils and StatusBar handler records use constructor parameter properties
and store `(sprite: Sprite) => void` callbacks. Adding a signature name cannot
supply the missing physical value, callback or constructor authority.

Reuse the existing `createOwnedSpriteValues` and `createOwnedSpriteBridge`
foundation, its private object-reference and scene/body/physics/lifecycle checks,
and its current source-producer integration. The integrated foundation remains
subject to the pending implementation qualification and adoption; this amendment
does not claim that it is already available on public main. Do not introduce a
parallel Sprite owner, separate identity registry or new transport schema.

Extend that same private issued-value domain only through an actual unshadowed
`sprites.create` allocation with independently proved Image and kind inputs and
the existing current native constructor/receiver admission. Bind the exact body,
service, program and eligible scene. Completion of an arbitrary constructor is
not a substitute for initialization proof. Raw IDs, equal ID text, annotations,
public flags and names cannot issue values. Preserve existing untyped Sprite
results, revocation and canonical codec behavior. A representation or supplier
schema change requires a separate coordinated claim before adoption.

A callback-valued field may receive only an actual compatible closure through
its proved constructor or later writer. Preserve separate instances, live
captured cells, receiver identity, saved callback reads, replacement through
aliases and actual ordered argument evaluation. Prove each Sprite argument and
Number or Void result independently, including unused parameters. One retained
callback signature with Sprite input does not admit ordinary function syntax,
generic callbacks or neighboring SDK members automatically.

Constructor parameter properties require their actual parser-owned metadata,
unique lexical parameter and field identities, modifiers and corresponding
ordered constructor assignments to agree. Reprove this after each real
lowering. Do not remove metadata, skip the initialization writes or treat a
parameter annotation as a stored value. Preserve default/optional refusals,
constructor effects and completion, readonly/private/protected rules and the
existing partial-construction physical-update semantics. Unknown, duplicated,
foreign, changed or reordered metadata/writers refuse.

After this foundation qualifies, the coordinated
[handler-record Array extension](arcade-handler-record-arrays.md#proposed-coordinated-sprite-record-subset)
may transport that same issued Sprite domain through one concrete ordinary
handler type and its one fixed callback signature. It grants no direct callable
Array or general SDK collection domain. The bounded Scene/handler registry protocol described in the linked contract
requires its own current entry and lifecycle proof. `allOfKind` producers,
destroyed/flag queries, additional class control flow and other SDK members
retain their independent obligations and named refusals. Keep all
original class bodies and neighboring diagnostics; no class partition or stub
may create eligibility.

### Required affected qualification

Use complete source-shaped handler records and real physical Sprites. Two
instances must retain distinct callbacks and bodies; aliases and saved callback
reads must observe the proper old or replacement action. Prove arguments are
evaluated once in order, a pausing Void callback completes before its caller,
and a changed current callback or Sprite input changes the actual result.
Reject annotation-only values, equal raw ID text, forged/extra-field transports,
wrong signatures, unknown or later writers, extracted receivers, changed
constructor metadata and foreign/stale/destroyed/scene-ineligible bodies.

Require source and current Blocks reproof, Code, same/fresh SB3, edited fields,
save/reopen and actual current export/reimport. Native Stop/restart/clear/Load,
disposal, callback failure and pending-completion controls must preserve the
existing owners. Qualify genuine selected-original and edited-export inputs;
never replay an unchanged successful original merely to read it. An admitted
official artifact must separately exercise visible authoring and assets. Record
missing GUI controls and public-route defaults explicitly. No native result
establishes GUI availability, whole-library compatibility or corpus credit.
