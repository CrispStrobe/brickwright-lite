# Physical Number inputs in Arrays value operations

## Observed authoring gap

An actual current `arrays_valueBinary` addition with connected `math_number`
shadows containing 20 and 1 evaluates to String `"201"`. The equivalent text
shadows correctly produce that String. Source imports can conceal this gap by
wrapping Number literals in existing numeric operators; an authored Number
must retain its intent without that wrapper.

## Implementation ownership

Codex owns a narrow shared current-input utility and coordinated Arrays supplier
adoption. Reuse the existing privately issued synchronous primitive execution
loan and exact current shadow cache lineage. A Number conversion requires the
actual current finite `math_number` leaf, input/parent connection, cached
operation, argument identity, runtime/target and active thread. Text, numeric
text variables, foreign/stale/disconnected producers and fabricated utility
objects cannot gain that interpretation. Do not change generic Scratch shadow
semantics or use an annotation or desired result type as producer authority.

Extract reusable input ownership into a shared VM utility without weakening
existing Arcade managed-call checks. Arrays operations must opt in through
explicit opcode and value-input roles. Coordinate the canonical extension in
CrispStrobe/extensions and generated consumer bundle, exact pins, notices and
hashes. Host interpretation is optional for standalone extension compatibility;
its absence preserves that host's existing behavior. Do not edit generated
extension strings independently of their canonical source.

First freeze the arithmetic, unary, comparison and truthiness value boundaries.
Audit Array value construction and reference writes separately, with the same
Number-versus-text distinction, before widening the role table. Existing
legacy JSON parsing, scalar item-return behavior and all reference identity,
undefined/null, Image, callable and lifetime protocols remain intact.

## Acceptance

- Real current Number 20 plus Number 1 is Number 21; text inputs remain String
  `"201"`. Check mixed operands, minus, fractional values, negative zero,
  comparison and truthiness. Bind relevant semantics to selected original
  evidence; no host JavaScript assumption for PXT-specific operations.
- Actual graph edits must change values through native execution, Code,
  same/fresh SB3 and current export/reimport. Preserve real operand order and
  once-only effects. No retained-source restoration or synthetic runtime.
- Exercise input/cache/parent/argument/opcode mutations, foreign targets,
  copied args, stopped/replaced threads, reset/load/dispose and direct calls.
  Existing managed Number boundary regressions must remain unchanged.
- Qualify canonical supplier checks before exact consumer adoption. Preserve
  every genuine failure and record reviewed head, actual merge base/tree and
  every enabled check. No supplier pin update from an unqualified candidate.
- Verify actual visible operator menus and authored Number/text blocks in the
  hosted editor, then save/reopen and export. Native current-graph proof alone
  is not a completed user GUI journey.

This work grants no new source callback/class/SDK domain, canonical word or
complete-game promotion. Raw corpus counts and authenticated complete-context
qualification remain separate observations.

## Candidate implementation checkpoint

The shared runtime interpreter now has an explicit opcode/input-role table.
Existing managed consumers retain their checks, while the four Array value
operations receive only their listed value sockets. Fixed Font selector
ownership uses the same extracted cached-operation checker with its existing
error contract. The engine overlay migrates only recognized prior ownership
markers and refuses unknown shapes; reapplication is idempotent.

The separate [supplier PR48](https://github.com/CrispStrobe/extensions/pull/48)
adds the optional host hook. Sixteen supplier controls and two independent
source reviews pass. Candidate canonical source loaded through the production
adapter and modified native runtime passes nine current-block cases, correcting
four retained baseline failures. Six role/migration controls and thirteen
existing managed/Font controls pass. The first native attempt lacked the new
support module in the test loader; that failure is preserved and the loader now
requires matching installed bytes for the new shared modules too.

This checkpoint does not update the shipped supplier pin or generated bundle.
Saved-project, edited export/reimport, original and hosted GUI qualification
remain separate gates. It does not resolve wider Array construction or write
input boundaries.
