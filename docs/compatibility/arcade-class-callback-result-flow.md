# Ordinary class callback effects and conditional results

## Proposed scope

Extend the proved ordinary class callback profile with owned `void` Arrows and
conditional generic method results. This is a source and current Blocks proof,
not permission from a return annotation. Keep the numeric callable gate and the
existing Number/String class profile independent.

The concrete dependency shape is StatusBar's `applyChange<T>`: retain the same
status object, test its presence, call `action(status)`, run `updateDisplay()`,
update the image, and return the saved action result. An absent status returns
genuine Undefined. The [MIT StatusBar v0.4.1 source](https://github.com/jwunderl/pxt-status-bar/blob/v0.4.1/status-bar.ts)
contains both Number getters and setters whose actions have no result. Preserve
the copyright and MIT notice if any source is incorporated.

First implement this ordering in independently authored ordinary classes. The
status object's display/image followups are ordinary managed methods and scalar
observations in that control. This does not substitute those observations for
the physical Sprite or Image ABI needed by the real library. Physical Sprite
parameters, intrinsic ancestry, scene frame registration and StatusBar graphics
remain separate admission requirements. Do not prune the library to claim its
whole context is supported.

## Directed branch proof

Every admitted `If` arm has its own producer and writer environment. Prove both
arms even when one observed invocation selects only one. Merge possible values
and writes at the continuation; a declaration or annotation cannot manufacture
a class instance, callback, primitive or initialized field. Preserve actual
alias identity and field writes in each arm. Unknown, foreign or incompatible
writers remain refusals, including writers in adjacent bodies and other targets.

First conditions cover proved Boolean values and presence tests of actual
ordinary object-or-Undefined producers. An absent typed field retains actual
Undefined; do not initialize it to zero, null or a fabricated object. Field
reads and callbacks before construction completes retain their existing named
refusals. Explicit null is distinct and remains outside this first presence
profile. A guard cannot turn an opaque producer into an ordinary object.

An action with a proved `void` signature completes with genuine Undefined.
Calling it must preserve its field mutations and complete its managed
continuation before display/image followups and caller statements. A pausing
action uses the existing managed continuation. No Promise wrapper, discarded
side effect or invented numeric result represents completion.

For a generic method, keep invocation-local substitution. Its successful arm
returns the actual action result; its absent arm returns actual Undefined.
Record a separately validated body result-flow certificate on the actual
method, rather than relaxing every Number/String result check. The certificate
must identify the current procedure, connected branch/return producers and
writers, and remain bound to the sealed current class graph. Completion may
accept Undefined only for that proved method and actual invocation. Never grant
it from a method name, `T` annotation, HAT, caller label or cached argument.

Export preserves the selected PXT method declaration and current branch bodies.
Reconstructed source passes the same complete-program producer proof. No global
Any or nullable signature widening follows. Unsupported union syntax, generic
constraints/defaults, recursive effects, loops, optional arguments, dynamic
callees, Array domains and module callable globals remain named gaps.

## Editable project and lifetime authority

Validate actual class registrations, method definitions, parameter mapping,
connected `If` substack boundaries, ordered arguments and every return/writer.
Disconnected writers, changed branch bodies, duplicated definitions, cyclic
input chains and foreign targets cannot reuse a prior result-flow certificate.
Generated locals need real dominating writers on every reading path, and their
names must preserve authored locals/formals. A branch-local temporary cannot
become a proof for a sibling branch or a later forward read.

Readonly and private access retain actual lexical ownership. A constructor-created
Arrow has no constructor write privilege. Stop and reload invalidate unfinished
calls and cached result authority. Restart after a valid edit creates fresh
source/current-body proof; disposal must not run a delayed followup.

## Acceptance

Required independently authored controls include:

- Number, String and Void actions on the same retained state object; two
  instances and aliases; a successful and absent state path; renamed classes.
- Actual mutation, display followup, image followup and caller order, with a
  pausing action and exact saved return value or Undefined.
- Code reparse, editable branch/action Blocks, same and fresh SB3, current export,
  actual changed original export execution and reimport.
- Stop/reload during the action; no late display/image update or stale receiver.
- Wrong result/writer in either arm, non-void fallthrough lacking a proved absent
  path, opaque cast in the condition, null conflation, generic narrowing,
  disconnected same/foreign target writes, formal overwrite and branch-local
  forward read. Each must retain a named refusal.

Use actual selected SDK controls for genuinely new source/export inputs, with
compiled input/binary/result retention and unchanged consumed guards. Reuse
successful originals only after complete input-byte equality. Preserve first
failures. Hosted GUI qualification must separately show editable action/branch
bodies, visible state/followup observations, Code, fresh save and actual original
export/reimport in an admitted official artifact. No corpus, whole-game or full
StatusBar compatibility promotion follows from these prerequisite controls.

## Ownership and publication order

The class owner owns new branch/result-flow helpers, strict class descriptor and
native completion integration, source/current-project gate extensions, and
focused tests. Coordinate `class-callable-source-flow.js`, class result/provider
metadata, `lower-callable-values.js`, `lower-object-classes.js`,
`object-class-export.js`, `callable-export-graph.js` and the optional native class
provider with their existing owners. Preserve Font intrinsic exclusion and its
independently proved producers. Numeric v1/default gates, vocabulary, pins and
frame phase remain unchanged.

Merge this documentation claim with enabled checks and reviewed/landed tree
equality before product admission changes. Then qualify the bounded whole
vertical slice; a pure branch helper alone is not completion.

## First implementation boundary

The first connected method shape saves one backing ordinary-class field, tests
its presence, retains one action result in the present arm, calls zero-argument
Void followups on that same saved receiver, and returns the retained result.
The absent arm returns actual Undefined. Other branch layouts, conditional
allocations and callback creation need separate current-body qualification.
Void actions used as effects are included; storing Void in a module variable
requires a separate declaration/export domain and remains unsupported. The
first fixture retaining such a cell is kept as a diagnostic control.

Native, Code, same/fresh saved-project and exported-source reimport controls
are implementation evidence. Selected-original and hosted GUI qualification
are still pending for this slice. No StatusBar graphics or complete-project
promotion follows from its scalar followup observations.
