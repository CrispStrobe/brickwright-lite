# Arcade per-player score Number producers

Status: proposed ownership contract; implementation waits for this claim's
normal qualified merge. A source proof is not native or GUI qualification.

## First bounded surface

Extend the existing ordinary primitive SDK Number proof to coexist with actual
per-player score operations. Support the unchanged, unshadowed zero-argument
`info.score()` and `info.player1.score()`, `info.player2.score()`,
`info.player3.score()` and `info.player4.score()` calls as Number producers only after independently
proving the actual SDK API and its current native implementation. Retain the
existing direct `info` census and its obligations. A valid fixed-player
`setScore` or `changeScoreBy` call must not invalidate an unrelated valid score
read merely because its receiver has another member level.

Resolve the complete lexical receiver and exact member/call structure. Inspect
all actual accesses and writers throughout the complete current executable
source, including later and unused functions. Bind the selected player to the
actual API and its supported fixed-player native reporter. Neither namespace
spelling, a return annotation, an opcode nor a syntactically similar object
supplies Number authority. The existing lexical SDK classifier is a receiver
classification, not an API certificate.

Use an explicit closed per-player access census. Refuse root or player/member
replacement, computed access, extraction, aliases, escapes, construction,
generic invocation, extra score arguments and unknown effects that can alter
the admitted receiver. Shadowed user objects retain their independent ordinary
semantics and cannot borrow SDK authority. Nested or indirect mutation routes
must not bypass the complete census. Preserve argument evaluation and existing
API diagnostics; do not clear an obligation, suppress a refusal or grant all
results from the namespace to make an export clean.

## Ownership and implementation boundary

Own the narrow source proof in
`overlay/scratch-gui/src/lib/bw-makecode/ordinary-primitive-sdk-number-source.js`,
its existing `source-value-producers.js` consumer integration if necessary,
focused source/current-export and native controls, and documentation. Also own
only the existing score Number proof's fixed-player argument binding in
`overlay/scratch-vm/src/extensions/crispstrobe/arcade/console-inspect-values.js`.
This coordinates the existing primitive inspection/score owner for finite
players one through four; it introduces no new ticket role or runtime body.
Coordinate an exact lexical receiver helper change before touching shared
classification. The scene-clock producer remains independent and unchanged.

Begin from a reviewed composition containing the current ordinary primitive
constraint and native fixed-player score foundations; public adoption must
include and qualify those foundations. Inspect actual SDK and adopted native
implementations before issuance. Keep current physical reporter ownership,
argument validation, Stop/load and failure behavior. This claim authorizes no
new runtime semantics, private ticket role, module alias, dependency pin or
broad SDK type seed. Beyond this same-role fixed-player proof extension, any
required runtime behavior change needs separately coordinated scope.

The physical proof must bind the exact supported literal player in the current
reporter's connected `PLAYER` shadow, actual cached shadow, actual argument
object and current native Number result. Matching membership in a player set
is insufficient: a player-two source/shadow cannot borrow a player-three cached
argument or another invocation. Do not coerce reference/tag/getter lookalikes
into literal player authority. Dynamic reporters, unsupported player values,
malformed/foreign sockets and ambiguous or stale caches keep named refusals.
Preserve every genuine registration/adapter/method/source-owner check,
exact graph/cache parent ownership, active operation/result checks and
Stop/load/disposal lifetime boundary. No direct-service or actual score body,
writer, HUD or event semantic change is authorized. If the actual completion
cannot establish Number under those checks, retain the refusal.
