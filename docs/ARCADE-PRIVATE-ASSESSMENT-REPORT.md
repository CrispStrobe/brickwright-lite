# Independent static report DATA admission

`admitReportData({reportJson, progressJsonl, expectationJson})` checks the complete static report and progress journal against independently admitted expectations. It imports only Node crypto. It never imports the converter, producer parser, VM, SDK, filesystem or network code. Return values and input/error details stay private.

The expectation JSON binds an explicit `inputMode`, actual source commit, corpus commit, catalogue hash, input-file content-multiset hash, vendor-pin JSON hash and MakeCode-version JSON hash. The original `catalogue` invocation supplies zero positional files and all 225 ordered catalogue identities (184 RAW_BASELINE, then 41 RETAINED_CONTEXT). The optional `positional-context` mode instead supplies 184 ordered raw filenames and 41 RETAINED_CONTEXT catalogue identities. The optional mode refuses a different semantic kind census rather than relabeling additional baselines as retained contexts. Keep the original all-catalogue invocation for the replacement assessment so its baseline lineage metadata remains intact. Context records are exactly `{id, kind, target, name}`. The filenames must be those actually passed inside the isolated converter namespace. The caller must obtain expectations from independent source/input admission; copying identities out of the report does not establish them.

The reader requires all 225 rows in order and recomputes the stage tally. Returned counts distinguish the 184 logical baseline subjects and 41 retained contexts from the physical positional-file and catalogue-subject counts. Failed/malformed inputs, unsupported diagnostics and failed retained original compiles remain in the returned unmodified report. It checks clean matching source endpoints, dependency hashes, selected catalogue subjects and the unchanged declarative corpus field (`commitVerified: false`). That false field is not a failure: external Git-object admission is the authority; this reader never rewrites the CLI's provenance claim.

Static scope requires offline fetching policy, an empty prepared tally, no preparation or journey, and no row-level compiler or execution results. The exact emitted `compile: null` sentinel on a failed raw TypeScript import is preserved without granting a compiler result. Nested qualification fields must retain the emitted static-only values. Raw/contextual catch rows retain their original reason and exception graph without inventing missing qualification or context objects. These stricter scope checks belong to this static assessment, not a restriction on the general CLI. The journal must have contiguous sequence numbers, monotonic timestamps, the complete ordered subject begin/capture pairs and a final reports-finished event. The reader does not infer successful conversion from journal completion.

Bounds are fixed: 64 MiB decoded report JSON, 8 MiB expectation/journal, 65,536 journal events and 16 KiB per event. This API accepts primitive strings, not compressed files or paths. A separate receiver must authenticate and bound decompression before passing report text here. The report must retain the CLI's exact native pretty JSON with a terminal newline; journal events and expectation use exact compact native JSON. This roundtrip rejects duplicate keys, nonfinite numbers and ambiguous encodings.

Completeness is a DATA check, not proof of producer origin, run success, stable intermediate inputs or dependency installation. Official run/artifact admission, isolation/resource closure, before/after source/input/dependency guards and independent review of conversion observations remain mandatory. Never derive SDK, runtime, full-game or GUI equivalence from this API. Source controls use a synthetic full 225-row fixture with preserved errors and corruptions of identities, rows, tallies, scope and journal completion; no corpus execution is implied.
