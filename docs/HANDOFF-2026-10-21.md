## Rules every WP inherits

- Fix the product, never weaken a test, threshold or assertion. A test expectation changes only when it is
  provably stale against shipped behaviour or an owner decision, and the commit message cites which.
- Every refusal or acceptance extension carries a wrong-input probe that must still be refused.
- Prove "intermittent" with evidence (it passes on main, or the failure doesn't involve the change) before
  re-running a job. A failure that recurs gets a root-cause fix, not retries or longer timeouts.
- CI: after #1121, a PR needs `ci:full` only when it touches browser-covered paths. When it does, add the
  label once on the final head. Merge only when every enabled exact-head check is SUCCESS, and check that the
  landed tree equals the predicted merge tree.
- **Pin bumps:** besides the 16 usual surfaces, `scripts/run-i80386-hdd-gui-actual.py` and
  `scripts/read-i80386-hdd-gui-originals.py` declare the bw-circuit-ui / bw-board / sb3-creator pins they
  expect. Search the full tree, not code search alone (its index lags).
- `packages/scratch-gui` is git-ignored but tracked: `git add -f` for its files.
