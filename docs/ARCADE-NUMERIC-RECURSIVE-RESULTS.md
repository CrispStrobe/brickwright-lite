## What the proof must establish

For an exact call in an admitted closed component, its value is a Number **if
that call returns normally**. This does not prove termination, suppress an
exception or replace an invocation with a constant. All original calls,
callees, arguments, their evaluation order and their effects remain in the
exported program.

The first slice covers synchronous module function declarations, immutable
direct aliases, Number arguments at every actual entry, invocation-local
Number stores and updates, branches and complete Number returns. It resolves
actual lexical bindings and every reference and caller. Alias initialization
must hold at all dynamic entries; the position of a reference inside a hoisted
function body is insufficient.

Use two distinct obligations:

1. Prove Number input and writer invariants and every possible normal return,
   under induction on a finite returning call tree.
2. Require a grounded syntactic return-dependency witness. This does not prove
   branch feasibility or existence of an actual returning invocation. A bare self/mutual cycle cannot
   seed its own Number result. A numeric base case also cannot excuse a String
   return or an opaque argument on another path.

Unknown entries, function escapes, callbacks, defaults/optional parameters,
captures, unknown calls, reflection, unsupported writers, missing returns and
mixed results decline the new fact. An annotation, function name, initialized
flag, observed runtime value or caller-supplied certificate provides no proof.
Any startup wrapper needs its own structural entry proof; its spelling gives
no authority and it gains no Number result merely by launching numeric calls.

The original own-data source baseline includes retained parameter/default
metadata before cloning or analysis projections. Observed source edits revoke
facts persistently, including an edit followed by restoration. Malformed or
inherited executable fields and private-token inputs do not acquire authority.

## Integration boundary

The general value graph retains cyclic `Opaque` results and its existing
immutable-function exclusions. It already propagates actual arguments and
initializes formal cells at entry; this work does not weaken those rules.

A separate private proof selects exact raw Call nodes. The native consumer
tracks only those actual identities through its internal views and stages a
private Number normal-result projection. Its original call remains present in
that analysis projection. The projection is not emitted as a replacement for
the source invocation and grants no input, Array, Image, receiver, capture or
general callable-body certificate. Exact recognized arithmetic helper bodies
may supply their existing contract; a matching helper name cannot.

When the new proof declines a program, the preceding numeric, Image and other
domain paths retain their original eligibility and refusal behavior.
