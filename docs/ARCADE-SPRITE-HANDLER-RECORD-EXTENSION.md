# Owned Sprite and handler-record claim extension

This amendment extends the existing [owned Sprite callback contract](compatibility/arcade-owned-sprite-class-callables.md) and [handler-record Array contract](compatibility/arcade-handler-record-arrays.md). The original contracts remain in place; implementation waits for the normal qualified merge of this amendment.

## Proposed coordinated Sprite handler-record extension

Implementation of this extension waits for the normal merge of this amendment.
The existing exclusions stay in force until the corresponding producer,
transport, current-project and lifetime proofs qualify. The first retained
Sprite Utils and StatusBar handler records use constructor parameter properties
and store `(sprite: Sprite) => void` callbacks. Adding a signature name cannot
supply the missing physical value, callback or constructor authority.

Reuse the existing `createOwnedSpriteValues` and `createOwnedSpriteBridge`
foundation, its private object-reference and scene/body/physics/lifecycle checks,
and its current source-producer integration. The integrated foundation remains
subject to the pending implementation qualification and adoption; this amendment
does not claim that it is already available on public main. Do not introduce a
parallel Sprite owner, separate identity registry or new transport schema.

Extend that same private issued-value domain only through an actual unshadowed
`sprites.create` allocation with independently proved Image and kind inputs and
the existing current native constructor/receiver admission. Bind the exact body,
service, program and eligible scene. Completion of an arbitrary constructor is
not a substitute for initialization proof. Raw IDs, equal ID text, annotations,
public flags and names cannot issue values. Preserve existing untyped Sprite
results, revocation and canonical codec behavior. A representation or supplier
schema change requires a separate coordinated claim before adoption.

A callback-valued field may receive only an actual compatible closure through
its proved constructor or later writer. Preserve separate instances, live
captured cells, receiver identity, saved callback reads, replacement through
aliases and actual ordered argument evaluation. Prove each Sprite argument and
Number or Void result independently, including unused parameters. One retained
callback signature with Sprite input does not admit ordinary function syntax,
generic callbacks or neighboring SDK members automatically.

Constructor parameter properties require their actual parser-owned metadata,
unique lexical parameter and field identities, modifiers and corresponding
ordered constructor assignments to agree. Reprove this after each real
lowering. Do not remove metadata, skip the initialization writes or treat a
parameter annotation as a stored value. Preserve default/optional refusals,
constructor effects and completion, readonly/private/protected rules and the
existing partial-construction physical-update semantics. Unknown, duplicated,
foreign, changed or reordered metadata/writers refuse.

After this foundation qualifies, the coordinated
[handler-record Array extension](#proposed-coordinated-sprite-record-subset)
may transport that same issued Sprite domain through one concrete ordinary
handler type and its one fixed callback signature. It grants no direct callable
Array or general SDK collection domain. The bounded Scene/handler registry protocol described in the linked contract
requires its own current entry and lifecycle proof. `allOfKind` producers,
destroyed/flag queries, additional class control flow and other SDK members
retain their independent obligations and named refusals. Keep all
original class bodies and neighboring diagnostics; no class partition or stub
may create eligibility.

### Coordinated source envelope

Coordinate the existing Sprite, class/callable, handler-Array, current-export and
managed-lifetime owners before editing shared surfaces. Extend the existing
`owned-sprite-values.js`, `owned-sprite-bridge.js` and their actual
`index.js` integration; reuse the current source-value producer and canonical
callable/record owners. Own only focused tests and narrow proof extensions in
those existing helpers. No parallel `sdk-sprite-*` ownership subsystem or
independent callback registry is authorized. Optional hooks are limited to actual producer/type/writer
and raw-ingress checks in:

- `callable-flow.js`, `callable-class-descriptors.js`,
  `class-callable-source-flow.js` and `class-callable-source-gate.js`;
- `lower-callable-values.js`, `object-class-source-structure.js`,
  `lower-object-classes.js`, `class-callable-plan.js` and its existing generator;
- `object-class-export.js`, `class-callable-export-types.js`,
  `class-callable-export-provider.js` and `class-callable-default-project-gate.js`;
- native `class-callable-types.js`, `class-callable-metadata.js`,
  `class-callable-provider.js`, `class-callable-graph.js` and
  `class-callable-host.js`, plus the generated plan validator;
- the existing Arcade runtime factory/field/callback integration only where
  necessary to issue or validate the same actual Sprite value, without changing
  physical Sprite algorithms, scheduling or legacy untyped results.

The frontend files above are under
`overlay/scratch-gui/src/lib/bw-makecode/`; native files are under
`overlay/scratch-vm/src/extensions/crispstrobe/arcade/`. Coordinate a narrow
`arcade-translate.js` selection hook with its current owner; no independent
selection bypass is authorized. Further shared surfaces, vocabulary, pins or
codec schema changes require explicit coordination and their applicable claim.

### Required affected qualification

Use complete source-shaped handler records and real physical Sprites. Two
instances must retain distinct callbacks and bodies; aliases and saved callback
reads must observe the proper old or replacement action. Prove arguments are
evaluated once in order, a pausing Void callback completes before its caller,
and a changed current callback or Sprite input changes the actual result.
Reject annotation-only values, equal raw ID text, forged/extra-field transports,
wrong signatures, unknown or later writers, extracted receivers, changed
constructor metadata and foreign/stale/destroyed/scene-ineligible bodies.

Require source and current Blocks reproof, Code, same/fresh SB3, edited fields,
save/reopen and actual current export/reimport. Native Stop/restart/clear/Load,
disposal, callback failure and pending-completion controls must preserve the
existing owners. Qualify genuine selected-original and edited-export inputs;
never replay an unchanged successful original merely to read it. An admitted
official artifact must separately exercise visible authoring and assets. Record
missing GUI controls and public-route defaults explicitly. No native result
establishes GUI availability, whole-library compatibility or corpus credit.

## Proposed coordinated Sprite record subset

Implementation waits for this amendment's normal merge and for the physical
issued-value foundation in the
[owned Sprite contract](#proposed-coordinated-sprite-handler-record-extension).
The original primitive-only subset and its no-SDK-values exclusion remain
unchanged until that foundation qualifies. This extension adds only one
concrete ordinary handler class per actual Array and one exact callback
signature whose Sprite input carries that private authority. Start with Void
callbacks and independently proved primitive fields; Number results need their
own complete result proof. No direct callable Arrays, mixed record classes,
Sprite inheritance or arbitrary SDK collection inputs follow.

Every insertion, replacement, removal, index/read-presence and callback read
must retain the existing Array, ordinary object and callable owners plus the
actual Sprite owner. A live record or Array cannot revive a revoked Sprite or
callback. Validate original raw ingress before any codec/heap normalization;
an inert element signature, saved field or equal Sprite ID text issues no
value. Constructor parameter-property metadata must satisfy the linked exact
parameter/field/ordered-writer proof, not a name or annotation shortcut.

Extend the existing handler-record producer/current-project proof and native
class/callback owners through coordinated hooks in the linked source envelope.
Reuse the existing owned Sprite values and bridge; create no second Sprite or
callback owner. Preserve
the existing canonical Array operations and allocation/alias behavior. A new
canonical element schema, reference kind or supplier word is separately claimed
and qualified before adoption; there is no implicit pin or codec change.

Exercise two real records, a shared Array alias, saved record/action reads,
callback replacement and removal, then genuine invocation with an issued
Sprite. Preserve the full callback and class bodies, captured effects,
argument order, pause/exception completion and current edits. Retain all
primitive registry adversaries and add forged/stale/foreign physical values,
replaced bodies, scene changes and lifecycle cancellation. Same/fresh saved
projects, actual current export/reimport, selected originals and visible
editing remain mandatory independent gates.

### Bounded Scene registry protocol

For the selected handler records, prove the actual Scene object and its owned
registry Array, the exact registration call, inserted record identity and the
actual callback entry that reads that same current record. Bind the actual
native Sprite constructor and constructor parameter-property schema to ordered
writes. The presently supported Image-only callback schema must be explicitly
extended through the same producer, field and current-project proof; neither a
Sprite annotation nor a parameter-property modifier supplies a value. Do not
assume that unrelated fields have initialized, suppress partial-construction
updates or filter records merely because construction is incomplete.

Retain complete Scene, handler and callback bodies and all module initialization
effects. Prove each actual entry's Scene eligibility, registration lifetime,
Array alias/writer/read presence and Stop/load/dispose revocation with the
existing managed owners. Qualify real SpriteUpdateHandler,
SpriteKindUpdateHandler and StatusHandler constructor and callback flows, not
isolated replacement bodies. Unsupported Scene effects, `sprites.allOfKind`,
destroyed/flag filtering and other loops/control flow keep named refusals;
their presence cannot be erased to make an authentic package pass.
