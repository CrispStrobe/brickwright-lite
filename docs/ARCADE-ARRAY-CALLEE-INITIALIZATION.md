# Current Array initialization across ordinary calls

## Status and boundary

This is an ownership extension for a bounded current-project Array receiver initialization proof.
Merge the documentation claim before implementing it. Source review or a clean
export does not establish native, visible GUI or whole-project qualification.

A current project can allocate an ordinary Array in a procedure, push values,
assign that same reference to a global cell, return normally, and then read it
or register a callback which later reads it. The exporter must prove those
actual operations and their order. A declared Array type, eventual writer union,
shared-frame effect boolean or generated spelling cannot establish initialization,
element presence or index bounds.

## Actual current graph and mandatory initialization

Derive facts only from the actual connected current project graph. Bind each
fact to its physical block, target, variable ID and visible declaration, exact
procedure declaration and call target, argument/frame identity, owner and edges.
Check the complete writer, alias, caller and entry inventory, including orphan,
dynamic, captured and independently registered paths. Preserve current schemas,
producer compatibility and independent initialization obligations.

A callee summary may transfer a global Array initialization into a later caller
occurrence only when the actual ordinary call necessarily completes the proved
write before that continuation. Prove operands, full body and normal completion;
branches must establish the fact on every continuing path. Unsupported branches,
loops, recursion, exceptions, unknown calls, yields, early returns or reentrant
paths cannot be treated as empty or as successful initializers. Refuse whenever
the required ordering or completion is not proved.

The caller must already possess that initialization before each exact callback
registration that can reach a read. Join the unique physical registration and
handler token, complete ordinary helper ancestry and all alternative entries.
Never initialize a callback from an assumed first execution, eventual writer,
finite simulation of a repeating callback or another target's similarly named
cell. Keep unknown and early entry refusals.

## Preserve independent Array and element obligations

Reuse the actual current allocation, alias and complete writer graph. Keep each
fresh local allocation at its original call and evaluation position. A summary
may prove that the actual reference was initialized; it does not merge distinct
allocations, remove a writer, promote an ordinary Array to an artwork resource,
or narrow the value of an indexed element.

Preserve all mutation, escape, branch, completion and reentry effects relevant
to the summarized global write. If a callee can expose or invalidate a required
fact, prove the actual effect or refuse the summary. Retain the existing element
presence, nested-Array producer and index rules unchanged. The current failure
concerns the ordinary Array receiver initialization, not a demonstrated need for
new index evaluation or cross-procedure element-presence authority. Preserve
all original index arithmetic, operands, evaluation order, errors and defaults.

## Owned paths and coordination

Own the narrow initialization, mandatory callee-write proof in
`overlay/scratch-gui/src/lib/bw-makecode/array-reference-export-authority.js`,
a focused control module under `test/`, and this document. Coordinate any exact
existing allocation or expression helpers before editing their shared hooks.
The existing exporter handoff and ordinary Array emitter remain unchanged unless
an explicitly reviewed matching consumer hunk is required.

This extends current Array authority only. Shared-frame transport, source effect
profiles, source annotation/default policy, runtime, vocabulary, supplier and
dependency pins, workflows, class/managed/captured ownership and pending handler
value domains remain outside this claim. No effect boolean becomes a value,
resource, initialization or presence certificate.

## Required qualification

Preserve original failures and all current bodies, diagnostics and partial
results. Add positive current-graph initialization, exact alias/writer and
registration/helper-chain controls. Include missing, early,
conditional, multiple and ambiguous callers; mixed/null/Undefined writers;
wrong target/cell/frame; recursion, escape, throwing and yielding paths;
mutating or escaped writer inputs; unchanged nested/index refusals; copied graphs,
current edits and mutation-then-restoration refusal.

Qualify the affected callback fixture through actual public Code import, Blocks,
SB3 with all costume/sound roles, current export and fresh exported-source
reimport. Require all provided diagnostics and retain absent channels as absent.
Then qualify an affected genuine guest with the current source and native
implementation. Source/model tests alone do not permit a feature, GUI, corpus
or whole-project claim.

## Current implementation and open dialog boundary

The current source implementation proves mandatory Array initialization for
closed zero-argument ordinary procedures with supported linear bodies.
Parameterized calls, control flow and unproved effects retain their refusals.
Complete qualification, including affected native and GUI behavior, remains
pending.

Passing an Array through `as any` into `game.splash` remains unsupported for
the observed source shape, with the diagnostic
`game.splash() requires proven primitive text; opaque or unknown inspection is not implemented`.
Dedicated authoring controls for this conversion in Blocks and the GUI remain
unverified. Full compatibility remains an open goal.
