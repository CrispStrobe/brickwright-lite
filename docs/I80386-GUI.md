# Experimental 80386 AT in Circuits, Widgets, and Code

For the 2026-10-05 checkpoint, exact dependency boundary and concrete acceptance tasks, see [the x86 next-lane handoff](X86-NEXT-LANES.md). Upstream native page-fault diagnostics are separate from this functional GUI backend.

See [x86 loading scope](X86-LOADING-SCOPE.md) and the [upstream CLI/GUI loading guide](https://github.com/CrispStrobe/bw-board/blob/master/docs/X86-LOADING-GUIDE.md). Historical licensed-guest browser notes are retained in the [private documentation archive](https://github.com/CrispStrobe/brickwright-firmware-private). Public examples use freely licensed or freeware software.

Open **Manage machines** from the Code tab. For a local disk, select a raw `.img`/`.ima`/`.bin` hard-disk image and click **Boot disk**. Optionally select a DOSBox `.conf` first. The importer reads `imgmount c ... -size 512,sectors,heads,cylinders`; it never executes `[autoexec]` commands. The local disk always boots on the 386 AT, including when the DOSBox CPU setting is omitted, `auto`, or an older CPU. Without a config, the loader infers 4 heads and 17 sectors from the file size, up to 1024 cylinders. Explicit geometry must fit BIOS limits: 1–1024 cylinders, 1–16 heads, and 1–63 sectors. The image remains in this browser tab. A URL-based Machine Manager config is also supported; its HDD slot should name explicit CHS geometry. Media bytes are not saved to the project or machine library.

The separate **Boot FreeDOS VGA** action selects bw-board's named `freedos-vga` profile. Choose a 1.2 MB or 360 KB floppy, a type-1 306×4×17 HDD, or both; optional AT BIOS and VGA ROM file fields replace the bundled LGPL firmware. The action routes all selected bytes through the board media slots (`bios`, `vga-rom`, `hdd`, `floppy`) before reset, then mirrors `video()` into the Widgets screen. If both disks are selected, both are attached and the config lists the floppy first in boot order; the BIOS performs the boot. A saved or imported machine config can select the same route with `"machineConfig":"freedos-vga"` and the corresponding media slots. The older **Boot disk** action retains its arbitrary DOSBox CHS support through the custom-config path; the named preset deliberately requires its fixed HDD geometry.

The named profile keeps Machine Manager open until the browser target attaches. If a later firmware or media load fails, the error appears in the manager instead of closing the dialog. The Chromium gate uses synthetic disks to check that both selected images reach the adapter, the 720×400 Widgets canvas receives keyboard and mouse input, and a failed BIOS fetch leaves the error visible. It does not claim a FreeDOS guest boot in Chromium.

The separate [real FreeDOS interaction probe](I80386-FREEDOS-INTERACTION.md) boots external FreeDOS media and an owned marker disk in Chromium. Its October 7 corrected-build run passed real C: listing, fullscreen, pane growth, an owned guest PS/2 packet probe and a shell response after Circuits/Code switching with preserved output and increasing guest time. The exact app, probe and artifact identities are in the [acceptance receipt](receipts/2026-10-07-freedos-interaction-acceptance.json); earlier reboot failures remain documented. This is one bounded guest scenario, with mouse-driver, drag-outside-canvas and browser-reserved-key coverage still open.

The [board's source-bound headless browser-target receipt](https://github.com/CrispStrobe/bw-board/blob/d983253edbffd56ff18ded41387a15932d48f347/docs/receipts/2026-09-28-i80386-browser-target-freedos.json) ran 45.8 million bounded steps through `createDebugTarget`, the four media slots, `target.runFor`, `target.keyIn`, and `target.video`. It reached the FreeDOS A: prompt, mounted C:, and matched the ordinary CLI guest screen. This proves the adapter path with pinned external media; it does not exercise Lite's browser widget or establish broader guest compatibility.

Without selected ROM files, the boot path uses the bundled free Bochs BIOS and VGA option ROM with the experimental 386 AT and its optional PS/2 mouse port. On boot, the VGA frame appears as a large interactive screen in the **Widgets** pane; the pane's **Full screen** button expands that screen to the display. Click the screen to focus it. IBM PC set-1 keyboard make/break codes, pointer movement, and left/right/middle button changes go to the running machine when the board profile has mouse enabled. Positive pointer `dy` means screen down. A separate keyboard widget, if declared, still works through its existing ASCII-to-scancode queue. The debugger screen remains available in the Circuits/Code dock.

For experimental native block execution, check **Native blocks (experimental)** on a saved i80386 row in Machine Manager, then run that machine. The local **Boot disk** and **Boot FreeDOS VGA** shortcuts each have their own checkbox for the current image; those choices are not persisted. A machine config can also declare `"nativeBlocks": true` at the top level. The saved-machine setting is off when omitted. The debugger batches eligible instructions while running, and uses ordinary instruction execution for stepping, breakpoints, watches, and debug event subscribers. Unsupported native blocks also fall back to ordinary execution.

The guest must enable PS/2 mouse reporting before pointer packets are accepted. Keyboard and pointer input are live; the experimental 386 target still refuses architectural checkpoint/replay. The browser may reserve keys such as Escape while in full-screen mode. The GUI does not bundle proprietary guest media, and a local file selection is not persisted across reloads.

The Widgets screen uses pointer capture for button drags, including in full screen, but does not request Pointer Lock. Relative movement therefore stops when the pointer reaches the screen edge.
