# Experimental 80386 AT in the GUI

A functional `i80386` Machine Manager config boots through the persistent debugger used by the Circuits and Code tabs. Give its boot slot a BIOS/ATA image URL and explicit disk geometry, for example `{cylinders:1000,heads:4,sectors:17}` for a 34,816,000-byte raw HDD. The Machine Manager resolves the media and sends `geometry` with the media-load event; the runner passes it to the AT ATA device and sets the matching CMOS geometry. Without the geometry, the runner's legacy 306/4/17 default is used and larger disks may not boot correctly.

The runner fetches the bundled free Bochs BIOS and VGA option ROM, enables the optional 8042 PS/2 auxiliary port, and offers its `video()` frame in the debugger's screen. A config with a `source:'video'` display widget also mirrors that frame into the Widgets pane. IBM PC set-1 keyboard make/break codes go to the runner when the debugger screen has focus. On the 386 screen, pointer movement and left/right/middle buttons go to `mouseIn({dx,dy,buttons})`; positive `dy` means screen down. The browser releases held mouse buttons when the pointer leaves the screen or the runner is torn down. The guest must enable PS/2 mouse reporting before packets are accepted.

Current limits: the Widgets pane's mirrored VGA face is display-only; use the debugger screen for mouse input. Pointer movement is bounded by the browser screen element because pointer lock is not used. Mouse input is live and is not recorded for debugger replay; the experimental 386 target already refuses architectural checkpoint/replay. The GUI does not bundle or distribute commercial DOS/Windows media. A user-supplied media URL must be reachable from the browser and satisfy the Machine Manager's media rules.
