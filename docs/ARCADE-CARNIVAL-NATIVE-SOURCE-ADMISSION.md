# Carnival package provenance and selected native APIs

Status: proposed coordinated extension of the Carnival host and dependency
import lanes. Merge this contract before implementation. Existing direct
Carnival Code support does not qualify an authentic dependency-package import.

## Observed boundary

The current asynchronous MakeCode import resolves declared dependency source
before translating the project. A real Carnival package therefore introduces
its namespace declarations, which ordinary namespace lowering binds and
rewrites. The direct Carnival primitive translator instead recognizes the
original unbound API call. A dependency-free source precheck cannot certify the
different package-prepared route.

Retain the original GUI failure and its actual input/diagnostic boundaries.
Replacing the expected Carnival command with arbitrary generated global text,
or running a separate direct Code fixture, cannot close that import failure.
Characterize the full actual resolved files, order, resources, provenance,
diagnostics and resulting graph before changing an assertion.

## Coordinated ownership

Extend the existing Carnival scoring/dialog host and authoring lane at the
shared dependency/native-source boundary. Own narrowly coordinated changes in
`overlay/scratch-gui/src/lib/bw-makecode/native-source-admission.js`, its
Carnival-specific `carnival-source-admission.generated.js` companion and narrow
source-identity generator if needed, `dependency-project.js`, and the exact
provenance handoff to `arcade-translate.js` and `namespace-bindings.js`. Coordinate an exact shared helper hunk
before editing it; unrelated adapters and ordinary namespace behavior remain
owned by their existing lanes.

Own focused source, initialization, current Code/Blocks/export, native and
affected GUI controls, the Carnival browser verifier, documentation and this
lane entry. Existing retained Carnival source/generator/native-host files may
be inspected as the implementation foundation. A required runtime or generator
semantic change needs explicit coordinated scope before editing; this contract
does not silently extend the native implementation to every package API.

Preserve other editor/importer ownership, dependency pins, fetch/license policy,
worker/compiler behavior, ordinary primitive producer proofs and other native
adapters. No package-name, namespace-prefix or opcode-only admission is allowed.

## Exact source and complete module effects

Begin with the retained original
[Carnival v0.0.7 source](https://github.com/microsoft/arcade-carnival/blob/915caca4a2d83a7071df59407a9987992c083750/carnival.ts)
and its [MIT notice](https://github.com/microsoft/arcade-carnival/blob/915caca4a2d83a7071df59407a9987992c083750/LICENSE).
Bind the actual resolved package identity, source files, complete bodies,
resources and ordering to their reviewed native counterparts. Exact source
identity is necessary; it does not itself prove behavior or complete coverage.
Changed bytes, extra files, different versions or ambiguous resolution cannot
inherit an old receipt.

Audit the entire original module initialization and all possible entries.
Preserve all five original `SpriteKind` allocations in their actual order,
numeric identity and relationship to other source/dependency kind allocations.
Preserve shared data, resources, registration, default state and every other
observable initializer. Lazy native host setup cannot stand in for that proof.
Repeated import, Stop/load/restart and current export must not duplicate or
reorder initialization or borrow a previous program's state.

The first selected surface is `carnival.startCountdownGame`,
`carnival.onGameOverExpanded` and `carnival.customGameOverExpanded`, together
with their actual style/scoring enums and already implemented internal
countdown/scoring/dialog helpers. Bind each current use to the exact original
declaration and proved native body, including argument/default evaluation,
callback ownership, effects, music, blocking order, persistent settings and
exception/lifetime behavior. Preserve current errors and cancellation.

Carry private provenance through namespace lowering or resolve the qualified
call before lowering with an explicit current binding proof. Retain the actual
source and body/coverage inventory. User shadows, namespace merges, aliases,
reassignment, extraction, dynamic access and indirect/callback entry must either
have complete current ownership/effect proof or keep named refusals. A generated
name, API spelling, type annotation or public source tag cannot supply it.

Do not skip the whole package, remove arbitrary helper bodies, add it to a
blanket vendored list or silently replace its complete namespace with three
calls. Unimplemented throwable, tracer, label, timer/HUD and other operations
remain explicit unsupported capabilities, with their complete source/body
provenance retained. Reachable unsupported bodies or uncertain initialization
keep the project partial. Any specialized translation representation must
explain actual declaration binding, complete initialization and selected-body
execution; it cannot hide missing support by pruning source or diagnostics.

## Qualification

1. Exercise authentic asynchronous package preparation/import on the current
   root and actual dependency graph, retaining every file/body/resource and
   provided diagnostic channel. Include changed source, extra files, wrong ref,
   shadow/merge/alias/indirect-call and unsupported-API controls. Keep existing
   adapters and dependency-free import behavior independently qualified.
2. Prove all five kind allocations and neighboring dependency/root allocations,
   actual shared state, callback/effect ordering and selected native body
   behavior. Include repeated initialization, failure, Stop/load/restart and
   foreign/stale program cases. Preserve unimplemented-operation refusals.
3. Use the actual package-imported result to produce primitive Code and visible
   Blocks. Edit current arguments, save, reopen and export from the actual
   connected graph without original-source restoration. Reimport the actual
   export with its authentic dependencies. A direct Code-authoring fixture
   stays separately labelled and cannot replace these routes.
4. Qualify affected native countdown/dialog/score/record/restart behavior and
   the retained original plus genuinely edited exported program. Use a fresh
   official frontend artifact for the actual GUI import, primitive Code/Blocks,
   run/save/reopen journey. Retain full graphs/assets, errors and raw partials.

Source/model controls are not native or GUI qualification. Preserve original
failures, thresholds and independent source/package/compiler checks. No full
Carnival library, whole-game compatibility or corpus-count promotion follows
from this selected API scope.
